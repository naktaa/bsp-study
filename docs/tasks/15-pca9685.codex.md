### 요구사항

**크기:** 드라이버 150줄 안팎. 기능을 줄여서 맞추고, 커널 스타일·처리 단위 사이 빈 줄 규칙은 줄 수보다 우선함

**매칭·등록**
- `of_device_id` `"nxp,pca9685-pwm"`, `i2c_device_id` `"pca9685"`, 둘 다 `MODULE_DEVICE_TABLE`
- 모듈 이름 `pca9685_simple`, `i2c_driver` 이름 `"pca9685-simple"`
- 채널 16개(`npwm` 16). ALL_LED 채널은 노출하지 않음
- `devm_pwmchip_alloc(dev, 16, sizeof(priv))` → `pwmchip_get_drvdata` → `devm_pwmchip_add`

**상태(priv)**
- `struct i2c_client *client`, `struct mutex lock`, request된 채널 비트(`DECLARE_BITMAP` 또는 `unsigned long` 하나)
- 레지스터 접근은 `i2c_smbus_read_byte_data`·`i2c_smbus_write_byte_data`·`i2c_smbus_write_i2c_block_data`·`i2c_smbus_read_i2c_block_data`만 씀. 반환값 음수는 그대로 전파

**레지스터(데이터시트, 업스트림과 같은 값)**
- MODE1 `0x00`(ALLCALL bit0, SUB3~1 bit1~3, SLEEP bit4, AI bit5), LEDn_ON_L = `0x06 + 4n`(ON_L, ON_H, OFF_L, OFF_H 순), PRE_SCALE `0xFE`
- full on = ON_H bit4, full off = OFF_H bit4(full off 우선)
- 25MHz 내부 클럭, 한 단계 `40ns × (prescale + 1)`, 카운터 4096

**`request`·`free`**
- `request`: lock 안에서 채널 비트 set. `free`: lock 안에서 clear. 출력은 건드리지 않음(업스트림과 같음)
- prescale 변경 가능 조건: request된 채널이 없거나, request된 채널이 자기 하나뿐일 때(업스트림 `pca9685_prescaler_can_change`와 같은 판정)

**`apply(chip, pwm, state)`** — 전체를 lock 안에서 처리
1. `state->polarity != PWM_POLARITY_NORMAL`이면 `-EINVAL`
2. `!state->enabled`면 해당 채널에 `{0, 0, 0, LED_FULL}` 4바이트를 쓰고 반환. prescale은 읽지도 바꾸지도 않음
3. 원하는 prescale = `period / (4096 × 40) − 1`(정수 나눗셈, 업스트림 식). 4096 × 40 × 4 ns 미만이면 `-EINVAL`, 255 초과면 255
4. 현재 PRE_SCALE을 읽어 원하는 값과 다를 때, 바꿀 수 없으면 길든 짧든 `-EINVAL`(업스트림은 긴 주기를 내림. 15-B는 단순화)
5. 바꿀 수 있고 현재 값과 다르면 MODE1 SLEEP=1 → PRE_SCALE 쓰기 → SLEEP=0 → `usleep_range(500, 1000)`. MODE1의 다른 비트는 유지(read-modify-write)
6. 실제 주기 = `4096 × 40 × (prescale + 1)`. duty 단계 = `min(duty_cycle, 실제 주기) / (40 × (prescale + 1))`(내림)
   - 0 → `{0, 0, 0, LED_FULL}`, 4096 이상 → `{0, LED_FULL, 0, 0}`, 그 외 → `{0, 0, duty & 0xff, (duty >> 8) & 0xf}`
7. LEDn 4바이트를 `i2c_smbus_write_i2c_block_data`로 한 번에 씀(MODE1 AI 필요)

**`get_state(chip, pwm, state)`**
- lock 안에서 LEDn 4바이트(`i2c_smbus_read_i2c_block_data`)와 PRE_SCALE을 읽음. 음수 반환만 전파하고 별도 검사는 두지 않음
- `period` = 실제 주기, `polarity` = normal
- OFF_H full off면 `enabled = false`, `duty_cycle = 0`. ON_H full on이면 `enabled = true`, `duty_cycle = period`. 그 외 `enabled = true`, `duty_cycle = ((off − on) & 0xfff) × 한 단계`
- 업스트림은 full off 채널을 `enabled, 0/주기`로 보고함(15-A 4-1). 이 차이는 의도한 것

**probe**
1. MODE1 = AI|SLEEP 쓰기(ALLCALL·SUBx 해제, 아직 잠든 상태). 실패하면 `dev_err_probe`(칩 응답 확인을 겸함)
2. ALL_LED_ON_L(`0xFA`)부터 `{0, 0, 0, LED_FULL}` 4바이트를 block 쓰기 한 번. 전 채널 full off
3. MODE1 = AI(SLEEP 해제) 쓰고 `usleep_range(500, 1000)`
4. `devm_add_action_or_reset`으로 "MODE1 SLEEP=1" 정리 동작을 등록한 뒤 `devm_pwmchip_add`. devm 역순 해제로 chip 해제 → SLEEP 순서가 됨. `.remove` 콜백은 두지 않음
- 순서 이유(주석으로 남김): 업스트림 remove 뒤에도 LEDn 값이 남아 있어서, 깨우기 전에 꺼 둬야 깨어나는 순간 이전 출력이 나가지 않음
- `i2c_check_functionality`는 넣을지 Codex가 판단해 구현 보고에 적음(빼면 첫 smbus 호출이 오류를 냄)

**Makefile**
- `obj-m := pca9685_simple.o`. 타깃 `all`(= modules)·`modules`·`deploy`(`scp pca9685_simple.ko $(PI_HOST):$(PI_MODULE_DIR)/`)·`clean`, `.PHONY`
- overlay·앱 타깃은 없음(15-A와 같은 `i2c-pwm-pca9685a`를 씀)

**스타일**
- 커널 스타일, 한글 주석은 의도·제약에만(probe 순서 이유, prescale 변경 조건, SLEEP 중에만 PRE_SCALE 쓰기)
- 함수 이름은 `pca9685_` 접두사의 짧은 이름(`pca9685_apply`, `pca9685_get_state`, `pca9685_set_sleep` 등)

  - 노트 예상값과 대조:
