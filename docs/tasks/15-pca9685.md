# 15 PCA9685 팬·틸트

상태: 완료 · 브랜치: `feat/pca9685` · Codex 지시서: [15-pca9685.codex.md](15-pca9685.codex.md) (15-B)
진행 장소: 노트북 + 기존 64GB 카드

## 목표
두 단계로 진행함.
- **15-A 업스트림 레퍼런스:** mainline `pwm-pca9685` + 기존 overlay로 pan(ch0)·tilt(ch1) 채널을 sysfs로 설정하고, 레지스터 값을 계산값과 대조해 15-B 비교 기준으로 남김
- **15-B 직접 provider 드라이버:** "업스트림 드라이버가 없는 장치"라고 가정하고 데이터시트 기준으로 PWM provider 드라이버를 작성(Codex 구현, 사용자는 구조 이해·검증). 같은 DT 노드에 드라이버만 바꿔 붙여 **같은 sysfs 설정에서 레지스터 값이 같은지** 비교

범위: DT/overlay 적용 → probe → pwmchip sysfs 설정 → 레지스터 값 확인(`i2cget -f`)까지. LED 출력 확인은 선택.

끝나면 다음을 설명할 수 있음.
- period·duty가 레지스터 값으로 바뀌는 과정
- 16채널이 prescaler 하나를 공유하는 제약
- DT는 하드웨어만 기술하고 드라이버 선택은 커널 쪽(config·모듈)에서 한다는 것
- VEDA의 `i2c-dev` 직접 제어와 커널 드라이버를 동시에 쓰면 안 되는 이유

## 알아둘 개념
1. **PWM 서브시스템:** provider 드라이버가 pwmchip(채널 `npwm`개)을 등록하면 사용자는 `/sys/class/pwm/pwmchipN/`에서 채널을 `export`하고 `period`·`duty_cycle`(ns)·`enable`을 씀. 커널은 이 값을 드라이버 콜백으로 넘김. 근거: `drivers/pwm/core.c`. 6.18에는 `/dev/pwmchipN` ioctl(`include/uapi/linux/pwm.h`)도 있음
2. **prescaler 하나 공유:** PCA9685는 25MHz 내부 클럭을 `PRE_SCALE + 1`로 나눠 4096단계로 셈
   - 20ms를 요청하면 드라이버가 prescale 121을 고름. 한 단계 40ns × 122 = 4880ns, 실제 주기 4096 × 4880 = 19,988,480ns. 리셋 기본값은 30(약 5.08ms, 197Hz)이고 probe는 PRE_SCALE을 쓰지 않음
   - duty 단계 수는 **내림**: `pca9685_round_waveform_tohw` L225 `duty = min(duty_length_ns, period_ns) / PCA9685_QUANTUM_NS(prescale)`(정수 나눗셈), OFF = (ON + duty) % 4096(L231), ON = 0
   - 다른 채널이 하나라도 export(request)돼 있으면 prescale을 바꿀 수 없음(`pca9685_prescaler_can_change`). 비트는 `enable`이 아니라 request 때 켜지고 `unexport`(free) 때 꺼짐(`pca9685_pwm_request`·`free`)
   - prescale을 못 바꿀 때 더 짧은 주기 요청은 `-EINVAL`(`round_waveform_tohw` → `core.c` `__pwm_apply`). 더 긴 주기 요청은 받아들이고 현재 prescale 주기로 내림(debugfs requested ≠ actual)
   - 그래서 **두 채널을 먼저 export하면 prescale이 리셋값 30에 묶여** 20ms 요청이 5.08ms로 내림 처리됨(서보에 약 200Hz). 첫 채널 하나만 export해 주기를 정한 뒤 다음 채널을 export함
   - `disable` 상태에서는 하드웨어를 확인하지 않아 period 쓰기가 항상 성공하고, 판정은 `enable` 때 함. `unexport`는 출력을 끄지 않으므로 항상 `enable 0` 뒤에 `unexport`함
   - 근거: `drivers/pwm/pwm-pca9685.c` L97, L207, L360~384, `core.c` `pwm_state2wf`·`pwm_unexport_child`
3. **DT는 하드웨어 기술:** binding `Documentation/devicetree/bindings/pwm/nxp,pca9685-pwm.txt`
   - 필수: `compatible = "nxp,pca9685-pwm"`, `#pwm-cells = <2>`(채널, period). index 16은 ALL 채널. 선택: `invert`, `open-drain`
   - 15-A·15-B 모두 같은 overlay(`i2c-pwm-pca9685a`)를 씀. 어떤 드라이버를 붙일지는 모듈 적재(blacklist·`bind`)로 정함. 제품에서는 커널 config로 정함
   - 드라이버가 0x40에 붙으면 `i2cdetect`에 `UU`로 보임. 이때 VEDA 방식으로 레지스터를 직접 쓰면 드라이버가 아는 상태(prescale·SLEEP)와 칩 상태가 어긋남

VEDA 기준(읽기 전용 `../VEDA_Final_Project/tank/src/ptz_control.cpp`, `tank/include/ptz_control.hpp`): 50Hz, pan = ch0, tilt = ch1, 펄스 500~2500µs = 0~180°, 중앙 90° = 1500µs.

## 백업·복구
- 부트 파일·`config.txt`를 바꾸지 않음. overlay는 런타임 `dtoverlay`로 적용하므로 재부팅하면 원래 상태로 돌아감
- VEDA 앱 등 `i2c-dev`로 0x40에 쓰는 코드는 실행하지 않음
- 드라이버가 붙어 있을 때(`UU`)는 `i2cget -f`로 **읽기만** 함. 드라이버가 붙지 않은 상태에서만 테스트 준비용 `i2cset`을 쓰고, 쓴 레지스터와 값을 결과에 남김(AGENTS.md)

## 칩 리셋 확인 (15-A 재실행 전, 15-B 검증 중)
PRE_SCALE·MODE1은 칩 VCC를 끊기 전까지 유지된다. 리셋 없이 돌리면 앞 실행의 prescale 121이 남아 4-1 순서 오류나 직접 작성한 드라이버의 PRE_SCALE 쓰기 경로가 가려진다. 처음 15-A를 실행할 때는 전원을 넣은 직후라 필요 없다.

먼저 데이터시트 기본값을 직접 쓴다. 드라이버가 붙지 않은 상태(`i2cdetect`에서 `40`이 `UU`가 아님)에서만 한다.

```bash
# [Pi] 채널 disable·unexport 후 드라이버 해제(rmmod 또는 modprobe -r)까지 한 상태
i2cdetect -y 1 | grep '^40'                    # 40 (UU가 아님)
i2cset -y 1 0x40 0x00 0x11                     # MODE1 기본값: SLEEP|ALLCALL. SLEEP 상태라 다음 PRE_SCALE 쓰기가 반영됨
i2cset -y 1 0x40 0xfe 0x1e                     # PRE_SCALE 기본값 30
i2cget -y 1 0x40 0x00; i2cget -y 1 0x40 0xfe
i2cdetect -y 1
```

확인: MODE1 `0x11` 또는 `0x91`(bit 7 RESTART 표시. 앞에서 PWM이 돌던 중 SLEEP에 들어가면 켜짐), PRE_SCALE `0x1e`, `40`·`68`·`70`(ALLCALL이 켜져 `70`이 다시 보임)
- LEDn 레지스터는 되돌리지 않는다. 남은 값은 직접 작성한 probe가 전 채널을 끄는지 확인하는 데 쓴다
- 값이 돌아오지 않거나 `i2cset`이 실패하면 전원 재인가: PCA9685 VCC 선(물리 17 레일)만 몇 초 뺐다가 다시 꽂는다. 그래도 `70`이 안 보이면 SDA·SCL 풀업을 통해 칩에 전원이 남았을 수 있으므로 Pi를 `poweroff` → 전원 분리 → 다시 켬

### 데이터시트 대조 (확인 필요)
레지스터 기본값과 동작은 데이터시트(PCA9685 Rev 4, MODE1·PRE_SCALE 레지스터 설명)와 대조해 결과에 적는다.
- MODE1 기본값 `0x11`(SLEEP·ALLCALL). 읽은 값은 `0x11` 또는 `0x91`(RESTART 표시) 가능
- PRE_SCALE 기본값 `0x1E`. SLEEP=1일 때만 쓰기가 반영됨
- SLEEP 해제 후 오실레이터 안정까지 500µs
- LEDn·ALL_LED 전원 직후 기본값(OFF_H full off 여부)

## 15-A 업스트림 레퍼런스

### 1. 배선 (전원 끈 상태)
| PCA9685 | 연결 | 물리 핀 |
| --- | --- | --- |
| VCC (로직) | Pi 3.3V, 브레드보드 3.3V 레일 경유(마이크 VDD와 공유) | 17 |
| GND | Pi GND | 20 |
| SDA | GPIO2 SDA1, 브레드보드에서 IMU SDA와 분기 | 3 |
| SCL | GPIO3 SCL1, 브레드보드에서 IMU SCL과 분기 | 5 |
| V+ (서보 전원 단자) | 연결 안 함 | — |
| ch0·ch1 | 서보 연결 안 함 | — |
| (선택) ch0 PWM 핀 | LED + 저항(330Ω~1kΩ) → GND | — |

- **전원을 넣기 전에 레일이 물리 17(3.3V)에서 오는지, 5V(물리 2·4)와 섞이지 않았는지 확인함.** 5V에 꽂으면 모듈 풀업 때문에 SDA·SCL이 5V가 됨
- 공유 지점(3.3V 레일, I2C1 분기)은 [bringup 공유 지점](../bringup.md) 표를 따름
- OE 핀은 연결하지 않음(기본). 상태는 결과에 적음

확인: **[붙여 주세요]** 배선 완료 여부, LED 연결 여부

### 2. 주소 확인
```bash
# [Pi]
sudo apt install -y i2c-tools

```

확인: **[붙여 주세요]** `40`, `70`(All Call), `68`(IMU, 드라이버가 붙어 있으면 `UU`)이 함께 보임 → I2C1 공유 배선 정상
- `68`이 사라졌으면 분기 배선(SDA·SCL 열)을 먼저 확인함.
- 업스트림 probe가 MODE1의 ALLCALL·SUBx를 끄므로(L470~474) 한 번 바인딩한 뒤에는 칩 전원을 다시 넣기 전까지 `70`이 안 보이는 게 정상

### 3. overlay 적용과 드라이버 등록
```bash
# [Pi]
sudo dtoverlay i2c-pwm-pca9685a
dtoverlay -l
lsmod | grep pca9685
dmesg | tail -5
for c in /sys/class/pwm/pwmchip*; do echo "$c $(cat $c/npwm) $(readlink -f $c/device)"; done

```

확인: **[붙여 주세요]** `pwm_pca9685` 적재, `npwm` 17(ch0~15 + ch16 ALL), 장치 경로에 `1-0040`, 드라이버 링크 끝이 `pca9685-pwm`, `i2cdetect`의 `40`이 `UU`
- 위 `for` 출력에서 `1-0040`인 pwmchip 번호를 4단계 `P`에 씀

### 4. 채널 설정과 레지스터 확인

#### 4-1. 주기 설정
ch0 하나만 export해 prescale을 정한 뒤 ch1을 export한다(개념 2).

```bash
# [Pi]
P=/sys/class/pwm/pwmchip0          # 3단계에서 확인한 번호
echo 0 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm0/period
echo 1500000  | sudo tee $P/pwm0/duty_cycle
echo 1        | sudo tee $P/pwm0/enable
sudo cat /sys/kernel/debug/pwm      # pwm-0 actual 1498160/19988480

echo 1 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm1/period
echo 1500000  | sudo tee $P/pwm1/duty_cycle
echo 1        | sudo tee $P/pwm1/enable
sudo cat /sys/kernel/debug/pwm
i2cget -f -y 1 0x40 0xfe            # PRE_SCALE
```

확인: **[붙여 주세요]** debugfs 출력과 PRE_SCALE. pwm-0·pwm-1 모두 actual 주기 `19988480`, PRE_SCALE `0x79`(121)
- actual이 `5079040`(PRE_SCALE `0x1e`) 등 20ms가 아니면 두 채널 `enable 0`·`unexport` 후 4-1을 다시 함

#### 4-2. duty별 레지스터 값
계산값(개념 2, prescale 121, 한 단계 4880ns, 내림):

| duty | 단계 | ON_L·ON_H | OFF_L·OFF_H |
| --- | --- | --- | --- |
| 1.0ms | 204 (0x0CC) | 0x00·0x00 | 0xcc·0x00 |
| 1.5ms | 307 (0x133) | 0x00·0x00 | 0x33·0x01 |
| 2.0ms | 409 (0x199) | 0x00·0x00 | 0x99·0x01 |

- 레지스터: ch0 = `0x06~0x09`, ch1 = `0x0a~0x0d`(ON_L, ON_H, OFF_L, OFF_H). disable된 채널은 OFF_H `0x10`(full off)
- MODE1(`0x00`)은 AI만 켜진 `0x20`으로 예상. RESTART(bit 7)가 함께 켜진 `0xa0`일 수 있음(데이터시트 확인 필요)
- VEDA(`ptz_control.cpp`, 20000µs 기준 `lround`)와 비교: 1.5ms는 307로 같고, 1.0ms·2.0ms는 VEDA가 205·410으로 반올림 방식 차이로 1단계 다름

```bash
# [Pi] 4단계 P 그대로
regs() { for r in 0x00 0x06 0x07 0x08 0x09 0x0a 0x0b 0x0c 0x0d 0xfe; do
  printf '%s=%s ' $r $(i2cget -f -y 1 0x40 $r); done; echo; }
for d in 1000000 1500000 2000000; do
  echo $d | sudo tee $P/pwm0/duty_cycle $P/pwm1/duty_cycle > /dev/null
  echo "duty $d"; regs
done
```

확인: **[붙여 주세요]** 세 줄의 레지스터 값. 위 표와 다르면 그대로 적음

(선택) LED: ch0에 LED를 달았으면 20ms 주기에서 duty 2ms(10%)와 18ms(90%)의 밝기를 비교한다. 50Hz라 깜빡임이 보일 수 있다.

```bash
# [Pi] 4단계 P 그대로
echo 2000000  | sudo tee $P/pwm0/duty_cycle; sleep 3
echo 18000000 | sudo tee $P/pwm0/duty_cycle; sleep 3
echo 1500000  | sudo tee $P/pwm0/duty_cycle
```

### 5. prescale 공유 확인
```bash
# [Pi] 4단계 P 그대로, ch0·ch1 export·enable 상태
# ① 더 짧은 주기: 거부
echo 10000000 | sudo tee $P/pwm1/period        # 기대: Invalid argument
cat $P/pwm1/period                             # 기대: 20000000 그대로

# ② 더 긴 주기: 받아들이고 현재 주기로 내림
echo 30000000 | sudo tee $P/pwm1/period        # 기대: 성공
sudo cat /sys/kernel/debug/pwm                 # pwm-1 requested 30000000, actual 19988480
echo 20000000 | sudo tee $P/pwm1/period
```

③은 ch1에 잠시 100Hz를 낸다.

```bash
# [Pi] 4단계 P 그대로
# ③ 다른 채널을 놓으면 바꿀 수 있음. unexport는 출력을 끄지 않으므로 먼저 disable
echo 0 | sudo tee $P/pwm0/enable
echo 0 | sudo tee $P/unexport
echo 0 | sudo tee $P/pwm1/enable
echo 10000000 | sudo tee $P/pwm1/period
echo 1        | sudo tee $P/pwm1/enable        # 기대: 성공(ch1만 request 상태)
sudo cat /sys/kernel/debug/pwm                 # pwm-1 actual 주기 9994240

# ④ 즉시 20ms로 되돌리고 4-1 순서로 ch0 복귀
echo 20000000 | sudo tee $P/pwm1/period
sudo cat /sys/kernel/debug/pwm                 # pwm-1 actual 19988480 확인
echo 0 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm0/period
echo 1500000  | sudo tee $P/pwm0/duty_cycle
echo 1        | sudo tee $P/pwm0/enable
sudo cat /sys/kernel/debug/pwm                 # 두 채널 actual 19988480 확인
```

⑤ (선택) 잘못된 export 순서: [칩 리셋 확인](#칩-리셋-확인-15-a-재실행-전-15-b-검증-중) 뒤 3단계를 다시 하고, ch0·ch1을 **먼저 둘 다 export**한 다음 4-1 설정을 하면 PRE_SCALE이 `0x1e`에 남고 debugfs actual이 `5079040`인지 `i2cget -f -y 1 0x40 0xfe`로 확인한다. 끝나면 6단계로 원복한다.

확인: **[붙여 주세요]** ①의 에러 메시지와 `cat` 값, ②·③·④ debugfs의 pwm-0·pwm-1 줄, ⑤를 했으면 PRE_SCALE·actual
- 9994240 = 4096 × 40ns × 61(prescale 60). 실측이 다르면 그대로 적음

### 6. 원복
```bash
# [Pi] 4단계 P 그대로
for ch in 0 1; do
  echo 0  | sudo tee $P/pwm$ch/enable
  echo $ch | sudo tee $P/unexport
done
sudo dtoverlay -r i2c-pwm-pca9685a
dtoverlay -l
sudo modprobe -r pwm_pca9685
lsmod | grep pca9685 || echo none
i2cdetect -y 1
```

확인: **[붙여 주세요]** overlay 목록 비어 있음, 모듈 없음, `40`이 다시 주소로 보임. 재부팅해도 같은 상태
- `70`은 보이지 않는 게 정상. probe가 ALLCALL을 껐고 모듈 해제로는 MODE1이 돌아오지 않음. Pi `reboot`는 3.3V가 유지되면 칩이 리셋되지 않아 그대로일 수 있음(확인 필요). Pi 전원을 분리했다 넣으면 다시 보임

## 비교 기준 (15-A → 15-B)
15-A 결과로 왼쪽 열을 채우고, 15-B에서 같은 명령을 돌려 오른쪽 열을 채운다.

| 항목 | 확인 명령(단계) | 15-A 업스트림 | 15-B 직접 작성 |

## 15-B 직접 provider 드라이버
학습용 최소 provider다. 업스트림과 모든 항목을 맞추는 것이 아니라, 핵심 경로(period → prescale → LEDn 레지스터)가 같은 값을 내는지 확인한다. 드라이버는 150줄 안팎을 목표로 한다.

18단계 Yocto 이미지에는 업스트림 `pwm-pca9685`를 쓰고 `pca9685_simple`은 넣지 않는다. 6.6 커널에 `devm_pwmchip_alloc`이 있는지는 18단계에서 소스로 확인 필요.

### 범위
- I2C client 기반 PWM provider 드라이버. `pwm_ops`는 `apply`·`get_state` + `request`·`free`(export 비트 관리)
  - 근거(6.18.59): `struct pwm_ops`(`include/linux/pwm.h` L293~313)는 waveform 콜백 세트와 legacy `apply`·`get_state` 중 하나를 씀. `pwm_ops_check`(`drivers/pwm/core.c` L1695)는 `write_waveform`이 없으면 `apply`를 필수로 보고, `get_state`가 없으면 `CONFIG_PWM_DEBUG`에서 경고함
  - waveform이 없으면 `__pwm_apply`가 `ops->apply`를 바로 부름(core.c L707). 반올림·`-EINVAL` 판정을 코어가 대신하지 않으므로 드라이버가 직접 함. debugfs actual은 `get_state` 결과
- 레지스터는 데이터시트 기준: MODE1(SLEEP, AI), PRE_SCALE(0xFE), LEDn_ON/OFF(`0x06 + 4n`)
- prescale 정책(업스트림보다 단순)
  - request/free 콜백에서 채널 비트를 켜고 끔. 다른 채널이 하나라도 request돼 있으면 prescale을 바꾸지 않음
  - 그때 prescale이 현재 값과 달라지는 요청은 길든 짧든 `-EINVAL`. 같은 prescale로 떨어지는 요청만 받음(업스트림은 긴 요청을 내림)
  - disable은 해당 채널 full off만 쓰고 별도 판정 없음. 판정은 enable될 때 함
- 데이터시트 제약
  - PRE_SCALE은 MODE1 SLEEP=1 상태에서만 씀: sleep → PRE_SCALE 쓰기 → wake
  - wake(SLEEP=0) 뒤 오실레이터 안정까지 500µs 대기
  - full on/off 비트(LEDn_ON_H·LEDn_OFF_H bit 4): disable·0%는 full off, 100%는 full on
  - MODE1 AI(auto-increment)를 켜고 `i2c_smbus_write_i2c_block_data`로 LEDn ON/OFF 4바이트를 한 번에 갱신
- probe: MODE1 = AI|SLEEP → ALL_LED(0xFA~0xFD)에 full off 한 번 → MODE1 = AI → 500µs
  - ALLCALL·SUBx를 끄고 AI를 켬(업스트림과 같음, 버스 충돌 방지)
  - SLEEP을 유지한 채 먼저 전 채널을 꺼 둠. 업스트림 remove 뒤에도 LEDn 값(예: 15-A의 1.5ms)이 남아 있어서, 깨어나는 순간 이전 출력이 나가지 않게 하려는 것
  - 이전 값에 의존하지 않음: MODE1은 읽지 않고 정한 값을 씀. PRE_SCALE은 probe에서 쓰지 않고 `apply`가 현재 값을 읽어 판정함(검증 1단계로 확인)
- remove: 업스트림과 같이 칩을 SLEEP으로 둠
- 16채널 노출. regmap·`pm_runtime`·GPIO chip·`invert`·`open-drain`·ALL 채널 노출·통계·재시도는 넣지 않음
- I2C 접근은 `i2c_smbus_*`를 직접 사용
- 6.18 API(읽기 확인): `devm_pwmchip_alloc` → `pwmchip_get_drvdata` → `devm_pwmchip_add` (`include/linux/pwm.h` L382, L485, L492)
- 매칭 표는 binding과 같음: `of_device_id` `"nxp,pca9685-pwm"`, `i2c_device_id` `"pca9685"`. 모듈 `pca9685_simple`, 드라이버 이름 `pca9685-simple`(업스트림 `pwm_pca9685`·`pca9685-pwm`과 구분)
- Codex 예정 파일: `examples/pca9685/pca9685_simple.c`, `examples/pca9685/Makefile`. overlay는 15-A와 같은 `i2c-pwm-pca9685a`를 쓰므로 만들지 않음

### 검증 흐름
같은 DT 노드에 드라이버만 바꿔 붙인다.

```text
+-----------------+       +----------------+
| DT node pca@40  | ----> | pwm-pca9685    |   15-A upstream
| nxp,pca9685-pwm |       +----------------+
|                 |       +----------------+
|                 | ----> | pca9685_simple |   15-B own driver
+-----------------+       +----------------+
```

리뷰 통과 후 아래 순서로 진행한다. 15-A 6단계(원복) 직후 상태에서 시작하고, 먼저 그 상태 그대로 적재해 probe가 이전 값에 의존하지 않는지 본 뒤, 기본값으로 초기화해 PRE_SCALE 쓰기 경로를 확인한다.

#### 0. 배포와 blacklist
```bash
# [노트북 WSL] ~/bspworkspace/bsp-study
make -C examples/pca9685 deploy
```

```bash
# [Pi]
echo 'blacklist pwm_pca9685' | sudo tee /etc/modprobe.d/pca9685-simple.conf
```

blacklist는 alias 자동 적재만 막는다. `modprobe pwm_pca9685`처럼 이름으로 직접 올리는 것은 막지 않는다.

#### 1. 15-A 직후 상태에서 바로 적재 (probe가 이전 값에 의존하지 않는지)
드라이버가 붙지 않은 상태에서 현재 값을 읽고, ch0에 15-A의 1.5ms 값을 일부러 남긴 뒤 적재한다.

```bash
# [Pi] 드라이버 없음(i2cdetect에서 40이 UU가 아님)
i2cget -y 1 0x40 0x00; i2cget -y 1 0x40 0xfe          # 15-A 직후 예상: MODE1 0x30(SLEEP|AI), PRE_SCALE 0x79
i2cset -y 1 0x40 0x06 0x00; i2cset -y 1 0x40 0x07 0x00
i2cset -y 1 0x40 0x08 0x33; i2cset -y 1 0x40 0x09 0x01  # ch0 = 1.5ms(307단계)를 남김
sudo dtoverlay i2c-pwm-pca9685a
lsmod | grep pca9685 || echo none                      # 업스트림이 자동 적재되지 않아야 함
sudo insmod ~/bsp/modules/pca9685_simple.ko
readlink /sys/bus/i2c/devices/1-0040/driver            # .../pca9685-simple
for c in /sys/class/pwm/pwmchip*; do echo "$c $(cat $c/npwm) $(readlink -f $c/device)"; done
for r in 0x00 0x06 0x07 0x08 0x09 0xfe; do printf '%s=%s ' $r $(i2cget -f -y 1 0x40 $r); done; echo
i2cdetect -y 1
```

확인: **[붙여 주세요]** 적재 전 MODE1·PRE_SCALE, `none`, 드라이버 `pca9685-simple`, `npwm` 16, `1-0040`, 적재 후 MODE1 `0x20`, ch0 OFF_H `0x10`(full off), PRE_SCALE은 적재 전과 같음(probe가 쓰지 않음), `40`은 `UU`
- 쓴 레지스터: `0x06~0x09` = `0x00 0x00 0x33 0x01`(ch0). 결과 칸에 그대로 적는다
- 적재 전 값이 `0x30`·`0x79`가 아니면(그사이 전원이 꺼졌던 경우 등) 읽은 값을 그대로 적고 진행한다

#### 2. 기본값으로 초기화 후 다시 적재 (PRE_SCALE 쓰기 경로)
rmmod와 insmod 사이에 기본값 쓰기를 빠뜨리면 PRE_SCALE이 `0x79`로 남아 이 단계의 의미가 없어진다. 아래 블록을 한 번에 실행한다([칩 리셋 확인](#칩-리셋-확인-15-a-재실행-전-15-b-검증-중)과 같은 명령).

```bash
# [Pi] 채널을 export하지 않은 상태
sudo rmmod pca9685_simple
i2cdetect -y 1 | grep '^40'                    # 40 (UU가 아님)
i2cset -y 1 0x40 0x00 0x11                     # MODE1 기본값 SLEEP|ALLCALL
i2cset -y 1 0x40 0xfe 0x1e                     # PRE_SCALE 기본값 30
i2cget -y 1 0x40 0x00; i2cget -y 1 0x40 0xfe   # 0x11 또는 0x91, 0x1e
i2cdetect -y 1                                 # 70 다시 보임

sudo insmod ~/bsp/modules/pca9685_simple.ko
for c in /sys/class/pwm/pwmchip*; do echo "$c $(cat $c/npwm) $(readlink -f $c/device)"; done
i2cget -f -y 1 0x40 0x00; i2cget -f -y 1 0x40 0xfe     # MODE1 0x20, PRE_SCALE 0x1e
i2cdetect -y 1                                         # 40은 UU, 70은 사라짐
```

확인: **[붙여 주세요]** 초기화 후 MODE1(`0x11`/`0x91`)·PRE_SCALE `0x1e`·`70` 보임, 다시 적재 후 MODE1 `0x20`, PRE_SCALE `0x1e`, `70` 사라짐
- 다음 단계의 `P`는 여기 `for` 출력에서 `1-0040`인 pwmchip으로 정한다(`P=/sys/class/pwm/pwmchipN`)

#### 3. 15-A와 같은 명령으로 비교
15-A [4-1](#4-1-주기-설정), [4-2](#4-2-duty별-레지스터-값), [5단계 ①~④](#5-prescale-공유-확인)를 같은 `P`로 그대로 실행한다.

확인: **[붙여 주세요]** 15-A와 같은 출력. 위 [비교 기준](#비교-기준-15-a--15-b) 표의 15-B 열을 채운다
- 예상 차이: request하지 않은 채널이 debugfs actual에서 `disabled`로 보임(`get_state`가 full off를 `enabled=false`로 돌려줌. 업스트림은 `enabled, 0/주기`)
- 예상 차이: 5② 두 채널 사용 중 30ms 요청이 `Invalid argument`(prescale 182 ≠ 현재 121이라 거부. 업스트림은 받고 내림)

#### 4. 원복과 업스트림 자동 바인딩 복귀
```bash
# [Pi] P 그대로
for ch in 0 1; do echo 0 | sudo tee $P/pwm$ch/enable; echo $ch | sudo tee $P/unexport; done
sudo rmmod pca9685_simple
i2cget -f -y 1 0x40 0x00                               # 0x30 (SLEEP|AI)
sudo dtoverlay -r i2c-pwm-pca9685a
sudo rm /etc/modprobe.d/pca9685-simple.conf
sudo dtoverlay i2c-pwm-pca9685a
sudo udevadm settle                                    # 모듈 자동 적재가 끝날 때까지 대기
readlink /sys/bus/i2c/devices/1-0040/driver            # .../pca9685-pwm
sudo dtoverlay -r i2c-pwm-pca9685a
sudo modprobe -r pwm_pca9685
lsmod | grep pca9685 || echo none
```

확인: **[붙여 주세요]** rmmod 뒤 MODE1 `0x30`, blacklist 삭제 후 업스트림 `pca9685-pwm` 자동 바인딩, 마지막 `none`

## 결과
대표 출력 몇 줄과 판단만 적는다. 원문 로그는 쌓지 않는다. 비교 값은 위 비교 기준 표에 적는다.

- 15-A 1 배선: 물리 17 → 3.3V 레일(마이크와 공유), 물리 3·5 → 브레드보드 분기(IMU와 공유), GND 물리 20. 처음에 `68`이 안 보이고 `i2ctransfer` WHO_AM_I가 `Remote I/O error` → IMU 쪽 SDA·SCL을 잘못 꽂은 것이 원인, 바로잡은 뒤 정상
- 15-A 2 주소: `i2cdetect -y 1`에 `40`·`68`·`70` → PCA9685와 IMU가 I2C1을 함께 씀
- 15-A 3 등록: `pwmchip0` `npwm` 17, `.../fe804000.i2c/i2c-1/1-0040`, 드라이버 `pca9685-pwm`, 모듈 `pwm_pca9685`(`.ko.xz`, 내장 아님). `i2cdetect`에 `40` → `UU`, `70` 사라짐(probe가 ALLCALL 끔), `68` 유지. dmesg `OF: overlay: WARNING: memory leak will occur if overlay removed`는 런타임 overlay의 `status` 변경 경고
- 15-A 4 레지스터: 4-1 ch0 먼저 export → pwm-0·pwm-1 actual `1498160/19988480`, PRE_SCALE `0x79` → 계산값과 같음. 4-2 1.0/1.5/2.0ms에서 ch0·ch1 모두 ON `0x00·0x00`, OFF `0xcc·0x00`/`0x33·0x01`/`0x99·0x01`, MODE1 `0x20`(AI만), PRE_SCALE `0x79` → 표와 일치(내림 확인). LED 확인은 하지 않음. request하지 않은 pwm-2~16도 actual이 `enabled, 0/19988480`으로 보임: `round_waveform_fromhw`가 full off 채널을 주기 = prescale 주기, duty 0으로 돌려주고 core `pwm_wf2state`는 주기가 0이 아니면 `enabled`로 표시함. 실제 출력은 꺼짐(full off)
- 15-A 5 prescale: ① 두 채널 request 상태에서 pwm1 10ms → `Invalid argument`, period `20000000` 유지 ② 30ms → 성공, requested `2000000/30000000`, actual `1995920/19988480`(내림) ③ ch0 disable·unexport 후 ch1 10ms 성공, actual `1998360/9994240`(prescale 60, 819단계). 이때 나머지 채널 actual 주기도 모두 9994240(prescale 공유) ④ 20ms 복귀 후 ch0 다시 export → 두 채널 actual 19988480. ⑤(잘못된 export 순서)는 하지 않음
- 15-A 6 원복: 두 채널 disable·unexport → overlay 제거(`No overlays loaded`) → `modprobe -r` 후 모듈 none. `i2cdetect`에 `40`·`68`, `70`은 안 보임(ALLCALL이 꺼진 채 칩 VCC 유지, 예상대로)
- 15-B 0 배포: `deploy`, blacklist 파일 `/etc/modprobe.d/pca9685-simple.conf` 생성
- 15-B 1 15-A 직후 적재: 적재 전 MODE1 `0x30`·PRE_SCALE `0x79`(15-A 직후 예상과 같음). 쓴 레지스터 ch0 `0x06~0x09` = `0x00 0x00 0x33 0x01`. 업스트림 미적재(`none`), 드라이버 `pca9685-simple`, `pwmchip0` `npwm` 16, `1-0040`. 적재 후 MODE1 `0x20`, ch0 `0x00 0x00 0x00 0x10`(OFF_L까지 0 → ALL_LED 쓰기가 전 채널에 반영됨), PRE_SCALE `0x79` 유지, `40` `UU`, `68` 유지 → probe가 이전 값에 의존하지 않음
- 15-B 2 초기화 후 재적재: 첫 시도는 `i2cset` 없이 rmmod → insmod만 해서 PRE_SCALE `0x79` 유지(재적재 자체는 MODE1 `0x20`·`UU`로 정상). 다시 실행: rmmod 뒤 `40`(UU 아님) → 쓴 레지스터 MODE1 `0x11`·PRE_SCALE `0x1e` → 읽기 `0x11`·`0x1e`, `70` 다시 보임(ALLCALL 복귀) → insmod 후 MODE1 `0x20`, PRE_SCALE `0x1e`(probe가 쓰지 않음), `70` 사라짐, `40` `UU`. 칩 초기화를 전원 재인가 없이 레지스터 쓰기로 대신할 수 있음을 확인
- 15-B 3 4-1: ch0 먼저 → pwm-0·pwm-1 actual `1498160/19988480`, PRE_SCALE `0x1e` → `0x79`(직접 작성한 드라이버의 SLEEP → PRE_SCALE → wake 경로 동작). request 안 한 채널은 `disabled, 0/19988480`
- 15-B 3 4-2: 1.0/1.5/2.0ms에서 ch0·ch1 ON `0x00·0x00`, OFF `0xcc·0x00`/`0x33·0x01`/`0x99·0x01`, MODE1 `0x20`, PRE_SCALE `0x79` → 15-A와 전부 같음
- 15-B 3 5: ① 10ms `Invalid argument`, period 20000000 유지 ② 30ms도 `Invalid argument`, requested `2000000/20000000` 유지(15-A는 받고 내림, 의도한 차이) ③ ch0 disable·unexport 후 ch1 10ms 성공, actual `1998360/9994240`, 나머지 채널 주기도 9994240 ④ 20ms 복귀 → ch0 다시 export → 두 채널 actual 19988480
- 15-B 4 원복(1차): disable·unexport → rmmod 뒤 MODE1 `0x30`(devm 정리 동작으로 SLEEP) → overlay 제거 → blacklist 삭제 → overlay 재적용 직후 `readlink`가 빈 출력 → `modprobe -r` 후 `none`. 업스트림 자동 바인딩은 확인 못 함
- 15-B 4 원복(2차): blacklist 파일 `removed` → overlay 재적용 → `udevadm settle` 후 `pwm_pca9685` 적재, `readlink`가 `pca9685-pwm` → overlay 제거·`modprobe -r` 후 `none`. 1차의 빈 출력은 udev가 모듈을 비동기로 올리기 전에 `readlink`가 실행된 타이밍 문제 → 원복 명령에 `udevadm settle`을 넣음
- 미검증 항목: 서보 실구동 미검증
