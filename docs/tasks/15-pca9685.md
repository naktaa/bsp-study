# 15 PCA9685 팬·틸트

상태: 대기 (15-A: PCA9685 보드 도착 후) · 브랜치: `feat/pca9685` · Codex 지시서: 15-A 완료 후 15-B용 `15-pca9685.codex.md` 생성 예정
진행 장소: 노트북 + 기존 64GB 카드. 같은 시기에 데스크톱에서 [12 Yocto](12-yocto-minimal.md)가 진행되며, Yocto 7단계 보드 확인 때만 카드를 바꿔 끼운다.

## 목표
두 단계로 진행함.
- **15-A 업스트림 레퍼런스:** mainline `pwm-pca9685` + 기존 overlay로 pan(ch0)·tilt(ch1) 채널을 sysfs로 설정하고, 레지스터 값을 계산값과 대조해 15-B 비교 기준으로 남김
- **15-B 직접 provider 드라이버:** "업스트림 드라이버가 없는 장치"라고 가정하고 데이터시트 기준으로 PWM provider 드라이버를 작성(Codex 구현, 사용자는 구조 이해·검증). 같은 DT 노드에 드라이버만 바꿔 붙여 **같은 sysfs 설정에서 레지스터 값이 같은지** 비교

범위: DT/overlay 적용 → probe → pwmchip sysfs 설정 → 레지스터 값 확인(`i2cget -f`)까지. 외부 전원을 쓰지 않으므로 서보 V+ 배선과 pan·tilt 실구동은 하지 않고 미검증으로 남김. LED 출력 확인은 선택.

끝나면 다음을 설명할 수 있음.
- period·duty가 레지스터 값으로 바뀌는 과정
- 16채널이 prescaler 하나를 공유하는 제약
- DT는 하드웨어만 기술하고 드라이버 선택은 커널 쪽(config·모듈)에서 한다는 것
- VEDA의 `i2c-dev` 직접 제어와 커널 드라이버를 동시에 쓰면 안 되는 이유

## 알아둘 개념
1. **PWM 서브시스템:** provider 드라이버가 pwmchip(채널 `npwm`개)을 등록하면 사용자는 `/sys/class/pwm/pwmchipN/`에서 채널을 `export`하고 `period`·`duty_cycle`(ns)·`enable`을 씀. 커널은 이 값을 드라이버 콜백으로 넘김. 근거: `drivers/pwm/core.c`. 6.18에는 `/dev/pwmchipN` ioctl(`include/uapi/linux/pwm.h`)도 있음
2. **prescaler 하나 공유:** PCA9685는 25MHz 내부 클럭을 `PRE_SCALE + 1`로 나눠 4096단계로 셈
   - 20ms를 요청하면 드라이버가 prescale 121을 고름. 한 단계 40ns × 122 = 4880ns, 실제 주기 4096 × 4880 = 19,988,480ns. 리셋 기본값은 30(약 5.08ms, 197Hz)이고 probe는 PRE_SCALE을 쓰지 않음
   - duty 단계 수는 **내림**: `pca9685_round_waveform_tohw` L225 `duty = min(duty_length_ns, period_ns) / PCA9685_QUANTUM_NS(prescale)`(정수 나눗셈), OFF = (ON + duty) % 4096(L231), ON = 0
   - 다른 채널이 하나라도 export(request)돼 있으면 prescale을 바꿀 수 없음(`pca9685_prescaler_can_change`). 비트는 `enable`이 아니라 request 때 켜지고 `unexport`(free) 때 꺼짐(`pca9685_pwm_request`·`free`)
   - prescale을 못 바꿀 때 더 짧은 주기 요청은 `-EINVAL`(`round_waveform_tohw` → `core.c` `__pwm_apply`). 더 긴 주기 요청은 받아들이고 현재 prescale 주기로 내림(debugfs requested ≠ actual)
   - 그래서 **두 채널을 먼저 export하면 prescale이 리셋값 30에 묶여** 20ms 요청이 5.08ms로 내림 처리됨(서보에 약 200Hz). 첫 채널 하나만 export해 주기를 정한 뒤 다음 채널을 export함
   - `disable` 상태에서는 하드웨어를 확인하지 않아 period 쓰기가 항상 성공하고, 판정은 `enable` 때 함. `unexport`는 출력을 끄지 않으므로 항상 `enable 0` 뒤에 `unexport`함
   - 근거: `drivers/pwm/pwm-pca9685.c` L97, L207, L360~384, `core.c` `pwm_state2wf`·`pwm_unexport_child`
3. **DT는 하드웨어 기술:** binding `Documentation/devicetree/bindings/pwm/nxp,pca9685-pwm.txt`
   - 필수: `compatible = "nxp,pca9685-pwm"`, `#pwm-cells = <2>`(채널, period). index 16은 ALL 채널. 선택: `invert`, `open-drain`
   - 15-A·15-B 모두 같은 overlay(`i2c-pwm-pca9685a`)를 씀. 어떤 드라이버를 붙일지는 모듈 적재(blacklist·`bind`)로 정함. 제품에서는 커널 config로 정함
   - 드라이버가 0x40에 붙으면 `i2cdetect`에 `UU`로 보임. 이때 VEDA 방식으로 레지스터를 직접 쓰면 드라이버가 아는 상태(prescale·SLEEP)와 칩 상태가 어긋남

VEDA 기준(읽기 전용 `../VEDA_Final_Project/tank/src/ptz_control.cpp`, `tank/include/ptz_control.hpp`): 50Hz, pan = ch0, tilt = ch1, 펄스 500~2500µs = 0~180°, 중앙 90° = 1500µs.

## 백업·복구
- 부트 파일·`config.txt`를 바꾸지 않음. overlay는 런타임 `dtoverlay`로 적용하므로 재부팅하면 원래 상태로 돌아감
- 서보 V+는 연결하지 않음
- VEDA 앱 등 `i2c-dev`로 0x40에 쓰는 코드는 실행하지 않음. 드라이버가 붙어 있을 때 `i2cget -f`로 **읽기만** 확인용으로 허용하고 `i2cset`은 쓰지 않음

## 칩 리셋 확인 (15-A 재실행 전, 15-B 검증 시작 전)
PRE_SCALE·MODE1은 칩 VCC를 끊기 전까지 유지된다. 리셋 없이 돌리면 앞 실행의 prescale 121이 남아 4-1 순서 오류나 직접 작성한 드라이버의 prescale 쓰기 버그가 가려진다. 처음 15-A를 실행할 때는 전원을 넣은 직후라 필요 없다.

1. 드라이버가 붙지 않은 상태로 둠: 채널 disable·unexport → `sudo dtoverlay -r i2c-pwm-pca9685a` → 모듈 해제
2. PCA9685 VCC 선(물리 17)을 뺐다가 몇 초 뒤 다시 꽂음
3. 리셋 판정:

```bash
# [Pi]
i2cdetect -y 1
```

확인: `40`과 함께 `70`이 다시 보이면 리셋됨(ALLCALL이 기본값으로 돌아옴). `70`이 안 보이면 SDA·SCL 풀업을 통해 칩에 전원이 남았을 수 있으므로 Pi를 `poweroff` → 전원 분리 → 다시 켜고 다시 확인함

## 15-A 업스트림 레퍼런스

### 1. 배선 (전원 끈 상태)
| PCA9685 | 연결 | 물리 핀 |
| --- | --- | --- |
| VCC (로직) | Pi 3.3V | 17 |
| GND | Pi GND | 20 |
| SDA | GPIO2 SDA1 | 3 |
| SCL | GPIO3 SCL1 | 5 |
| V+ (서보 전원 단자) | 연결 안 함 | — |
| ch0·ch1 | 서보 연결 안 함 | — |
| (선택) ch0 PWM 핀 | LED + 저항(330Ω~1kΩ) → GND | — |

- **VCC가 3.3V(물리 17)인지 전원을 넣기 전에 확인함.** 5V에 꽂으면 모듈 풀업 때문에 SDA·SCL이 5V가 됨
- OE 핀은 연결하지 않음(기본). 상태는 결과에 적음

확인: **[붙여 주세요]** 배선 완료 여부, LED 연결 여부

### 2. 주소 확인
```bash
# [Pi]
sudo apt install -y i2c-tools
i2cdetect -y 1
```

확인: **[붙여 주세요]** `40`, `70`(All Call)이 보임. IMU를 연결해 두었으면 `68`도 보임
- 업스트림 probe가 MODE1의 ALLCALL·SUBx를 끄므로(L470~474) 한 번 바인딩한 뒤에는 칩 전원을 다시 넣기 전까지 `70`이 안 보이는 게 정상

### 3. overlay 적용과 드라이버 등록
```bash
# [Pi]
sudo dtoverlay i2c-pwm-pca9685a
dtoverlay -l
lsmod | grep pca9685
dmesg | tail -5
for c in /sys/class/pwm/pwmchip*; do echo "$c $(cat $c/npwm) $(readlink -f $c/device)"; done
readlink /sys/bus/i2c/devices/1-0040/driver
i2cdetect -y 1
```

확인: **[붙여 주세요]** `pwm_pca9685` 적재, `npwm` 17(ch0~15 + ch16 ALL), 장치 경로에 `1-0040`, 드라이버 링크 끝이 `pca9685-pwm`, `i2cdetect`의 `40`이 `UU`
- 위 `for` 출력에서 `1-0040`인 pwmchip 번호를 4단계 `P`에 씀

### 4. 채널 설정과 레지스터 확인

#### 4-1. 주기 설정
ch0 하나만 export해 prescale을 정한 뒤 ch1을 export한다(개념 2).

```bash
# [Pi]
P=/sys/class/pwm/pwmchip0          # 3단계에서 확인한 번호
echo 0 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm0/period
echo 1500000  | sudo tee $P/pwm0/duty_cycle
echo 1        | sudo tee $P/pwm0/enable
sudo cat /sys/kernel/debug/pwm      # pwm-0 actual 1498160/19988480

echo 1 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm1/period
echo 1500000  | sudo tee $P/pwm1/duty_cycle
echo 1        | sudo tee $P/pwm1/enable
sudo cat /sys/kernel/debug/pwm
i2cget -f -y 1 0x40 0xfe            # PRE_SCALE
```

확인: **[붙여 주세요]** debugfs 출력과 PRE_SCALE. pwm-0·pwm-1 모두 actual 주기 `19988480`, PRE_SCALE `0x79`(121)
- actual이 `5079040`(PRE_SCALE `0x1e`) 등 20ms가 아니면 두 채널 `enable 0`·`unexport` 후 4-1을 다시 함

#### 4-2. duty별 레지스터 값
계산값(개념 2, prescale 121, 한 단계 4880ns, 내림):

| duty | 단계 | ON_L·ON_H | OFF_L·OFF_H |
| --- | --- | --- | --- |
| 1.0ms | 204 (0x0CC) | 0x00·0x00 | 0xcc·0x00 |
| 1.5ms | 307 (0x133) | 0x00·0x00 | 0x33·0x01 |
| 2.0ms | 409 (0x199) | 0x00·0x00 | 0x99·0x01 |

- 레지스터: ch0 = `0x06~0x09`, ch1 = `0x0a~0x0d`(ON_L, ON_H, OFF_L, OFF_H). disable된 채널은 OFF_H `0x10`(full off)
- MODE1(`0x00`)은 AI만 켜진 `0x20`으로 예상. RESTART(bit 7)가 함께 켜진 `0xa0`일 수 있음(데이터시트 확인 필요)
- VEDA(`ptz_control.cpp`, 20000µs 기준 `lround`)와 비교: 1.5ms는 307로 같고, 1.0ms·2.0ms는 VEDA가 205·410으로 반올림 방식 차이로 1단계 다름

```bash
# [Pi] 4단계 P 그대로
regs() { for r in 0x00 0x06 0x07 0x08 0x09 0x0a 0x0b 0x0c 0x0d 0xfe; do
  printf '%s=%s ' $r $(i2cget -f -y 1 0x40 $r); done; echo; }
for d in 1000000 1500000 2000000; do
  echo $d | sudo tee $P/pwm0/duty_cycle $P/pwm1/duty_cycle > /dev/null
  echo "duty $d"; regs
done
```

확인: **[붙여 주세요]** 세 줄의 레지스터 값. 위 표와 다르면 그대로 적음

(선택) LED: ch0에 LED를 달았으면 20ms 주기에서 duty 2ms(10%)와 18ms(90%)의 밝기를 비교한다. 50Hz라 깜빡임이 보일 수 있다.

```bash
# [Pi] 4단계 P 그대로
echo 2000000  | sudo tee $P/pwm0/duty_cycle; sleep 3
echo 18000000 | sudo tee $P/pwm0/duty_cycle; sleep 3
echo 1500000  | sudo tee $P/pwm0/duty_cycle
```

### 5. prescale 공유 확인
```bash
# [Pi] 4단계 P 그대로, ch0·ch1 export·enable 상태
# ① 더 짧은 주기: 거부
echo 10000000 | sudo tee $P/pwm1/period        # 기대: Invalid argument
cat $P/pwm1/period                             # 기대: 20000000 그대로

# ② 더 긴 주기: 받아들이고 현재 주기로 내림
echo 30000000 | sudo tee $P/pwm1/period        # 기대: 성공
sudo cat /sys/kernel/debug/pwm                 # pwm-1 requested 30000000, actual 19988480
echo 20000000 | sudo tee $P/pwm1/period
```

③은 ch1에 100Hz를 내지만 V+ 미연결이라 그대로 진행한다.

```bash
# [Pi] 4단계 P 그대로
# ③ 다른 채널을 놓으면 바꿀 수 있음. unexport는 출력을 끄지 않으므로 먼저 disable
echo 0 | sudo tee $P/pwm0/enable
echo 0 | sudo tee $P/unexport
echo 0 | sudo tee $P/pwm1/enable
echo 10000000 | sudo tee $P/pwm1/period
echo 1        | sudo tee $P/pwm1/enable        # 기대: 성공(ch1만 request 상태)
sudo cat /sys/kernel/debug/pwm                 # pwm-1 actual 주기 9994240

# ④ 즉시 20ms로 되돌리고 4-1 순서로 ch0 복귀
echo 20000000 | sudo tee $P/pwm1/period
sudo cat /sys/kernel/debug/pwm                 # pwm-1 actual 19988480 확인
echo 0 | sudo tee $P/export
echo 20000000 | sudo tee $P/pwm0/period
echo 1500000  | sudo tee $P/pwm0/duty_cycle
echo 1        | sudo tee $P/pwm0/enable
sudo cat /sys/kernel/debug/pwm                 # 두 채널 actual 19988480 확인
```

⑤ (선택) 잘못된 export 순서: [칩 리셋 확인](#칩-리셋-확인-15-a-재실행-전-15-b-검증-시작-전) 뒤 3단계를 다시 하고, ch0·ch1을 **먼저 둘 다 export**한 다음 4-1 설정을 하면 PRE_SCALE이 `0x1e`에 남고 debugfs actual이 `5079040`인지 `i2cget -f -y 1 0x40 0xfe`로 확인한다(15-B prescale 처리의 기준값). 끝나면 6단계로 원복한다.

확인: **[붙여 주세요]** ①의 에러 메시지와 `cat` 값, ②·③·④ debugfs의 pwm-0·pwm-1 줄, ⑤를 했으면 PRE_SCALE·actual
- 9994240 = 4096 × 40ns × 61(prescale 60). 실측이 다르면 그대로 적음

### 6. 원복
```bash
# [Pi] 4단계 P 그대로
for ch in 0 1; do
  echo 0  | sudo tee $P/pwm$ch/enable
  echo $ch | sudo tee $P/unexport
done
sudo dtoverlay -r i2c-pwm-pca9685a
dtoverlay -l
sudo modprobe -r pwm_pca9685
lsmod | grep pca9685 || echo none
i2cdetect -y 1
```

확인: **[붙여 주세요]** overlay 목록 비어 있음, 모듈 없음, `40`이 다시 주소로 보임. 재부팅해도 같은 상태
- `70`은 보이지 않는 게 정상. probe가 ALLCALL을 껐고 모듈 해제로는 MODE1이 돌아오지 않음. Pi `reboot`는 3.3V가 유지되면 칩이 리셋되지 않아 그대로일 수 있음(확인 필요). Pi 전원을 분리했다 넣으면 다시 보임

## 비교 기준 (15-A → 15-B)
15-A 결과로 왼쪽 열을 채우고, 15-B에서 같은 명령을 돌려 오른쪽 열을 채운다.

| 항목 | 확인 명령(단계) | 15-A 업스트림 | 15-B 직접 작성 |
| --- | --- | --- | --- |
| 바인딩 드라이버 | `readlink .../1-0040/driver` (3) | | |
| `npwm` | `cat $P/npwm` (3) | | 16 예정(ALL 채널 없음) |
| 20ms·1.5ms 설정 후 debugfs actual | `/sys/kernel/debug/pwm` (4-1) | | |
| PRE_SCALE·MODE1 | `i2cget -f` `0xfe`·`0x00` (4-2) | | |
| 1.0/1.5/2.0ms LEDn ON/OFF | `i2cget -f` `0x06~0x0d` (4-2) | | |
| 두 채널 export 상태에서 10ms 요청 | `tee $P/pwm1/period` (5 ①) | | |

| 해제 후 `i2cdetect` `40`·`70` | (6) | | |

## 15-B 직접 provider 드라이버 (계획)
15-A가 끝나면 이 섹션을 기준으로 Codex 지시서를 만든다. 세부 명령은 그때 확정한다.

### 범위
- I2C client 기반 PWM provider 드라이버. `pwm_ops`는 `apply`·`get_state` + `request`·`free`(export 비트 관리)
  - 근거(6.18.59): `struct pwm_ops`(`include/linux/pwm.h` L293~313)는 waveform 콜백 세트와 legacy `apply`·`get_state` 중 하나를 씀. `pwm_ops_check`(`drivers/pwm/core.c` L1695)는 `write_waveform`이 없으면 `apply`를 필수로 보고, `get_state`가 없으면 `CONFIG_PWM_DEBUG`에서 경고함
  - waveform이 없으면 `__pwm_apply`가 `ops->apply`를 바로 부름(core.c L707). 반올림·`-EINVAL` 판정을 코어가 대신하지 않으므로 드라이버가 직접 함. debugfs actual은 `get_state` 결과
- 레지스터는 데이터시트 기준: MODE1(SLEEP, AI), PRE_SCALE(0xFE), LEDn_ON/OFF(`0x06 + 4n`)
- prescale 정책은 업스트림과 같음(개념 2)
  - request/free 콜백에서 채널 비트를 켜고 끔. 다른 채널이 하나라도 request돼 있으면 prescale을 바꾸지 않음
  - 그때 현재 주기보다 짧은 요청은 `-EINVAL`, 긴 요청은 현재 prescale 주기로 내림
  - disable 상태의 period 쓰기는 하드웨어를 건드리지 않고, enable될 때 판정
- 데이터시트 제약
  - PRE_SCALE은 MODE1 SLEEP=1 상태에서만 씀: sleep → PRE_SCALE 쓰기 → wake
  - wake(SLEEP=0) 뒤 오실레이터 안정까지 500µs 대기
  - full on/off 비트(LEDn_ON_H·LEDn_OFF_H bit 4): disable·0%는 full off, 100%는 full on
  - MODE1 AI(auto-increment)를 켜고 `i2c_smbus_write_i2c_block_data`로 LEDn ON/OFF 4바이트를 한 번에 갱신
- probe
  - 칩을 깨움(SLEEP 해제 + 500µs). 전원 직후 기본값이 SLEEP이고, 업스트림이 remove 때 SLEEP으로 남김
  - MODE1의 ALLCALL·SUBx를 끄고 AI를 켬(업스트림과 같음, 버스 충돌 방지)
  - 모든 채널 full off로 초기화(채널별 LEDn_OFF_H bit 4. 업스트림과 방법이 다름, 차이 표 참고)
- remove: 업스트림과 같이 칩을 SLEEP으로 둠
- 16채널 노출. `invert`·`open-drain`·ALL 채널·GPIO chip·`pm_runtime`은 넣지 않음
- I2C 접근은 `i2c_smbus_*`를 직접 사용. regmap 전환은 선택
- 6.18 API(읽기 확인): `devm_pwmchip_alloc` → `pwmchip_get_drvdata` → `devm_pwmchip_add` (`include/linux/pwm.h` L382, L485, L492)
- 매칭 표는 binding과 같음: `of_device_id` `"nxp,pca9685-pwm"`, `i2c_device_id` `"pca9685"`. 모듈 `pca9685_simple`, 드라이버 이름 `pca9685-simple`(업스트림 `pwm_pca9685`·`pca9685-pwm`과 구분)
- Codex 예정 파일: `examples/pca9685/pca9685_simple.c`, `examples/pca9685/Makefile`. overlay는 15-A와 같은 `i2c-pwm-pca9685a`를 쓰므로 만들지 않음

### 검증 흐름 (예정)
같은 DT 노드에 드라이버만 바꿔 붙인다.

```text
+-----------------+       +----------------+
| DT node pca@40  | ----> | pwm-pca9685    |   15-A upstream
| nxp,pca9685-pwm |       +----------------+
|                 |       +----------------+
|                 | ----> | pca9685_simple |   15-B own driver
+-----------------+       +----------------+
```

0. [칩 리셋 확인](#칩-리셋-확인-15-a-재실행-전-15-b-검증-시작-전)으로 `70`이 다시 보이는 것을 확인(prescale 리셋값 30에서 시작)
1. `/etc/modprobe.d/`에 `blacklist pwm_pca9685` 파일을 만들어 업스트림 자동 적재를 막음
2. overlay 적용 → 직접 작성한 `pca9685_simple.ko`를 `insmod` → `readlink .../1-0040/driver`로 바인딩 확인
3. 15-A 3~5단계 명령을 같은 순서(4-1 ch0 먼저)로 실행해 비교 표 오른쪽 열을 채움. 비교 기준은 같은 sysfs 설정에서 레지스터 값이 같은가
4. 필요하면 `unbind`/`bind`로 재부팅 없이 두 드라이버를 바꿔 같은 테스트를 반복
5. 원복: 채널 disable·unexport → `rmmod` → overlay 제거 → blacklist 파일 삭제

### 비교할 구조 차이 (읽기 확인)
| 항목 | 업스트림 `pwm-pca9685.c` | 15-B |
| --- | --- | --- |
| 콜백 | waveform 콜백 `round_waveform_tohw`/`fromhw`(L389). 반올림과 `-EINVAL` 판정 일부를 PWM 코어가 함 | `apply`·`get_state`. 반올림·거부를 드라이버가 직접 함 |
| 채널 | 17(ch16 = ALL_LED, L80~83) | 16 |
| 레지스터 접근 | regmap | `i2c_smbus_*` |
| 전력 | `pm_runtime`: request된 채널이 없으면 SLEEP, probe 직후 SLEEP | probe에서 깨우고 remove까지 깨어 있음. remove 때 SLEEP |
| 0% duty | full off 비트 없이 ON = OFF(L224~244) | full off 비트 |
| ALLCALL·SUBx | probe에서 끔(L470~474) | 같음 |
| probe 출력 초기화 | ALL_LED 레지스터(0xFA~0xFD)에 `{0, LED_FULL, 0, LED_FULL}`를 한 번 씀(L480~481). 주석상 POR 기본값이며 full off가 우선이라 전 채널 꺼짐 | 채널별 LEDn_OFF_H에 full off를 씀(16번 쓰기). 결과(전 채널 꺼짐)는 같고 방법·ON_H 값이 다름. POR 기본값은 데이터시트 확인 필요 |
| 기타 | GPIO chip, `invert`·`open-drain` | 없음 |

### 15-B 완료 기준 (예정)
- [ ] 업스트림 blacklist 상태에서 `pca9685_simple`이 `1-0040`에 바인딩
