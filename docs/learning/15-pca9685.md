# PCA9685: 업스트림 PWM 드라이버 확인과 직접 작성한 provider 비교

## 1. 한눈에 보기

- **목적:** VEDA Final에서 사용자 공간 `i2c-dev`로 직접 쓰던 PCA9685(팬·틸트 서보용 PWM 칩)를 커널 PWM 서브시스템으로 다룬다. 먼저 업스트림 드라이버로 기준값을 만들고(15-A), "업스트림 드라이버가 없다"고 가정해 최소 provider를 직접 작성해 같은 sysfs 설정에서 같은 레지스터 값이 나오는지 비교했다(15-B).
- **기능:**
  - 15-A: mainline `pwm-pca9685` + 기존 overlay `i2c-pwm-pca9685a`
  - 15-B: 직접 작성한 [pca9685_simple.c](../../examples/pca9685/pca9685_simple.c)(legacy `apply`·`get_state`, `i2c_smbus_*`, 16채널, 243줄)
  - 같은 DT 노드에 blacklist로 드라이버만 바꿔 붙임
- **직접 작성 / 가져다 쓴 것:** 15-B provider [pca9685_simple.c](../../examples/pca9685/pca9685_simple.c)는 직접 작성했다. 15-A의 mainline `pwm-pca9685`, overlay `i2c-pwm-pca9685a`, PWM 코어 sysfs는 커널 것을 쓴다.
- **결과(사용자 보드 실행):**
  - 15-A: 20ms에서 PRE_SCALE `0x79`(121), 1.0/1.5/2.0ms의 LEDn 레지스터가 계산값(내림)과 일치. 두 채널을 쓰는 중 짧은 주기는 거부, 긴 주기는 내림
  - 15-B: 같은 설정에서 LEDn·PRE_SCALE·MODE1이 15-A와 모두 같음. 두 채널을 쓰는 중 주기 변경은 10ms·30ms 모두 거부(의도한 차이). probe가 이전 값에 의존하지 않음을 15-A 직후 상태에서 확인
  - 칩 초기화를 전원 재인가 대신 `i2cset` 기본값 쓰기로 대신함
  - 서보 실구동과 핀 파형은 확인하지 않음
- **관련 파일:**
  - 코드: [pca9685_simple.c](../../examples/pca9685/pca9685_simple.c), [Makefile](../../examples/pca9685/Makefile)
  - 작업: 노트 [15-pca9685](../tasks/15-pca9685.md), [Codex 지시서](../tasks/15-pca9685.codex.md)
  - 사양·배선: [hardware.md](../hardware.md#pca9685--sg90-팬틸트), [bringup.md 공유 지점](../bringup.md#40핀-한눈에-보기)
  - 커널 소스(`external/linux`, Git 대상 아님): `drivers/pwm/pwm-pca9685.c`, `drivers/pwm/core.c`, `include/linux/pwm.h`, `Documentation/devicetree/bindings/pwm/nxp,pca9685-pwm.txt`, overlay `arch/arm/boot/dts/overlays/i2c-pwm-pca9685a-overlay.dts`

## 2. 구조

**흐름:** `echo > /sys/class/pwm/pwmchip0/pwm0/duty_cycle` → PWM core(`pwm_apply`) → provider 콜백 → I2C(SMBus) 쓰기 → PCA9685 LEDn·PRE_SCALE 레지스터 → 칩 내부 카운터가 핀 출력.

```text
+------------------+      +-------------+      +--------------------+
| sysfs pwmchip0   | ---> | PWM core    | ---> | provider driver    |
| export / period  |      | pwm_apply   |      | pwm-pca9685 (15-A) |
| duty / enable    |      | debugfs pwm |      | pca9685_simple(15B)|
+------------------+      +-------------+      +---------+----------+
                                                         | i2c_smbus / regmap
                                                         v
+------------------+      +-------------+      +--------------------+
| DT overlay       | ---> | i2c-1 @0x40 | ---> | PCA9685            |
| i2c-pwm-pca9685a |      | fe804000    |      | MODE1 PRE_SCALE    |
| nxp,pca9685-pwm  |      +-------------+      | LEDn ON/OFF x16    |
+------------------+                           +--------------------+
```

| 계층 | 구성 요소 | 하는 일 |
| --- | --- | --- |
| 배선 | I2C1(물리 3·5) 분기, 3.3V 레일(물리 17) | IMU `0x68`과 버스 공유, 마이크와 3.3V 공유 |
| DT | `i2c-pwm-pca9685a` overlay | I2C1을 켜고 `nxp,pca9685-pwm` 노드(`reg = <0x40>`) 추가 |
| 드라이버 선택 | modprobe blacklist | DT는 그대로 두고 어떤 모듈이 붙을지만 바꿈 |
| provider | `pwm-pca9685` / `pca9685_simple` | period·duty를 prescale과 LEDn 레지스터로 변환 |
| 프레임워크 | PWM core | sysfs·debugfs 노출, request/free, legacy·waveform 경로 선택 |

## 3. 알아야 할 개념

### 왜 16채널이 주기를 하나만 쓸 수 있는가

PCA9685는 25MHz 내부 클럭을 `PRE_SCALE + 1`로 나눠 4096단계 카운터 하나를 돌린다. 채널은 이 카운터에서 켜고 끄는 시점(ON/OFF)만 따로 가진다. 그래서 주기는 칩 전체에 하나다. 20ms를 요청하면 prescale = `20000000 / (4096 × 40) − 1` = 121이고, 한 단계 40 × 122 = 4880ns, 실제 주기 4096 × 4880 = 19,988,480ns다. 15-A 5③에서 ch1만 10ms로 바꾸자 request하지 않은 채널의 actual 주기까지 모두 9,994,240ns로 바뀐 것이 이 공유를 보여 준다.

### 왜 다른 채널이 쓰는 중이면 주기를 못 바꾸는가

prescale을 바꾸면 이미 쓰고 있는 다른 채널(예: pan 서보)의 주기도 같이 바뀐다. 업스트림은 request된 채널이 없거나 자기 하나뿐일 때만 바꾼다(`pca9685_prescaler_can_change`). request 비트는 `enable`이 아니라 export(request) 때 켜지고 unexport(free) 때 꺼진다. 그래서 두 채널을 먼저 export하면 prescale이 리셋값 30(약 5.08ms)에 묶인다. 첫 채널만 export해 주기를 정한 뒤 다음 채널을 export해야 한다.

### 왜 같은 DT 노드에 드라이버만 바꿔 붙였는가

DT는 하드웨어(`nxp,pca9685-pwm`, I2C 주소)만 기술하고 어떤 드라이버를 쓸지는 커널 쪽에서 정한다. 15-B는 binding과 같은 compatible을 그대로 쓰고, `/etc/modprobe.d/`의 `blacklist pwm_pca9685`로 업스트림 자동 적재만 막은 뒤 `insmod`했다. 가짜 compatible을 만들면 DT가 드라이버 선택에 묶인다. 제품에서는 blacklist 대신 커널 config로 정한다.

### 왜 바인딩된 장치에는 `i2cget -f`로 읽기만 했는가

드라이버가 붙으면 `i2cdetect`에 `UU`로 보이고, 드라이버는 prescale·SLEEP 상태를 안다고 가정한다. 이때 사용자 공간에서 레지스터를 쓰면 드라이버가 아는 상태와 칩이 어긋난다(VEDA 방식과 커널 드라이버를 같이 쓰면 안 되는 이유). 그래서 바인딩 중에는 `i2cget -f`로 확인용 읽기만 하고, `i2cset`은 드라이버가 없을 때 테스트 준비에만 썼다(AGENTS.md 규칙).

### 왜 15-B는 waveform이 아니라 legacy `apply`를 썼는가

6.18 `struct pwm_ops`(`include/linux/pwm.h` L293)는 waveform 콜백 세트(`round_waveform_tohw` 등) 또는 legacy `apply`·`get_state` 중 하나를 쓴다. 업스트림은 waveform 방식이라 반올림과 일부 `-EINVAL` 판정을 core가 맡는다. legacy는 `__pwm_apply`가 `ops->apply`를 바로 부르므로(`core.c` L707) 반올림·거부를 드라이버가 직접 한다. 학습용으로는 period → prescale → 레지스터 변환이 한 함수에 다 보이는 legacy가 읽기 쉽다.

## 4. 구현 흐름

**probe** ([L179](../../examples/pca9685/pca9685_simple.c#L179))
1. `devm_pwmchip_alloc(dev, 16, ...)` → drvdata에 client·mutex
2. MODE1 = AI|SLEEP([L197](../../examples/pca9685/pca9685_simple.c#L197)): ALLCALL·SUBx를 끄고 AI(auto-increment)를 켜되 아직 잠든 상태
3. ALL_LED(0xFA)에 `{0, 0, 0, LED_FULL}` 한 번([L202](../../examples/pca9685/pca9685_simple.c#L202)): 전 채널 full off. 업스트림 remove 뒤에도 LEDn 값이 남아 있어서 깨우기 전에 끈다
4. MODE1 = AI, 500µs 대기([L207](../../examples/pca9685/pca9685_simple.c#L207)): 오실레이터 안정
5. SLEEP 정리 동작을 `devm_add_action_or_reset`으로 등록한 뒤 `devm_pwmchip_add`([L213](../../examples/pca9685/pca9685_simple.c#L213)). devm은 역순으로 풀리므로 해제 때 chip 제거 → SLEEP 순서가 된다

probe는 MODE1을 읽지 않고 정한 값을 쓰며 PRE_SCALE은 건드리지 않는다. 그래서 이전 상태에 결과가 좌우되지 않는다(15-B 검증 1단계).

**apply** ([L72](../../examples/pca9685/pca9685_simple.c#L72), 전체를 mutex 안에서)
1. disable이면 해당 채널 full off만 쓰고 끝(PRE_SCALE은 보지 않음)
2. prescale = `period / 163840 − 1`, 상한 255([L91](../../examples/pca9685/pca9685_simple.c#L91)). 655,360ns(prescale 3) 미만은 `-EINVAL`
3. 현재 PRE_SCALE과 다르면([L97](../../examples/pca9685/pca9685_simple.c#L97)): 다른 채널이 request돼 있으면 `-EINVAL`, 아니면 SLEEP → PRE_SCALE 쓰기 → wake → 500µs. PRE_SCALE은 SLEEP 중에만 쓰기가 반영된다
4. duty 단계 = `min(duty, 실제 주기) / 한 단계`(내림, [L120](../../examples/pca9685/pca9685_simple.c#L120)). 0이면 full off, 4096이면 full on, 그 외 ON=0·OFF=단계
5. LEDn 4바이트를 block 쓰기 한 번(AI 덕분에 0x06+4n부터 연속)

**get_state** ([L136](../../examples/pca9685/pca9685_simple.c#L136)): LEDn 4바이트와 PRE_SCALE을 읽어 period·duty를 계산한다. full off는 `enabled = false`로 돌려준다. debugfs의 actual은 이 값이다.

**업스트림과의 차이 (보드 확인)**

| 항목 | 업스트림 `pwm-pca9685` | `pca9685_simple` |
| --- | --- | --- |
| 콜백 | waveform(core가 일부 판정) | legacy `apply`·`get_state` |
| `npwm` | 17(ch16 = ALL_LED) | 16 |
| 다른 채널 사용 중 주기 변경 | 짧으면 거부, 길면 현재 주기로 내림 | prescale이 달라지면 모두 거부 |
| request 안 한 채널 debugfs actual | `enabled, 0/19988480` | `disabled, 0/19988480` |
| probe 출력 초기화 | ALL_LED `{0, LED_FULL, 0, LED_FULL}`, 깨우기는 `pm_runtime`이 함 | SLEEP 중 ALL_LED `{0, 0, 0, LED_FULL}` → 깨움 |
| 레지스터 접근·전력 | regmap, `pm_runtime`(request된 채널이 없으면 SLEEP) | `i2c_smbus_*`, probe부터 remove까지 깨어 있음 |
| 같음 | prescale 식, duty 내림, PRE_SCALE은 SLEEP 중에만 씀, ALLCALL·SUBx 끔, remove 때 SLEEP | |

업스트림의 `enabled, 0/주기`는 `round_waveform_fromhw`가 full off 채널을 주기 = prescale 주기, duty 0으로 돌려주고, core `pwm_wf2state`(`core.c` L80)가 주기가 0이 아니면 `enabled`로 표시하기 때문이다. 실제 출력은 둘 다 꺼져 있다.

**VEDA와의 차이:** `ptz_control.cpp`는 20,000µs 기준 `lround`로 단계를 반올림해 1.0/2.0ms가 205/410단계다. 커널 드라이버는 내림이라 204/409단계(OFF `0xcc·0x00`/`0x99·0x01`)이고, 1.5ms는 둘 다 307단계다.

<details><summary>재현 절차 (펼치기)</summary>

전체 단계와 출력은 [작업 노트](../tasks/15-pca9685.md)에 있다. 배선(전원 분리 상태): VCC → 3.3V 레일(물리 17, 마이크와 공유), GND → 물리 20, SDA·SCL → 물리 3·5에서 IMU와 브레드보드 분기. **VCC가 5V에 꽂히면 모듈 풀업 때문에 SDA·SCL이 5V가 되므로 전원 전에 확인한다.**

```bash
# [Pi] 15-A 업스트림. 시작 전 i2cdetect -y 1에 40·68·70
sudo dtoverlay i2c-pwm-pca9685a
sudo udevadm settle
readlink /sys/bus/i2c/devices/1-0040/driver            # .../pca9685-pwm
P=/sys/class/pwm/pwmchip0                              # npwm 17, 장치 1-0040인 번호
echo 0 | sudo tee $P/export                            # ch0 먼저(prescale을 정함)
echo 20000000 | sudo tee $P/pwm0/period
echo 1500000  | sudo tee $P/pwm0/duty_cycle
echo 1        | sudo tee $P/pwm0/enable
echo 1 | sudo tee $P/export                            # 그다음 ch1
echo 20000000 | sudo tee $P/pwm1/period
echo 1500000  | sudo tee $P/pwm1/duty_cycle
echo 1        | sudo tee $P/pwm1/enable
i2cget -f -y 1 0x40 0xfe                               # 0x79
for r in 0x06 0x07 0x08 0x09; do i2cget -f -y 1 0x40 $r; done   # 0x00 0x00 0x33 0x01
```

```bash
# [Pi] 원복(공통). unexport는 출력을 끄지 않으므로 disable 먼저
for ch in 0 1; do echo 0 | sudo tee $P/pwm$ch/enable; echo $ch | sudo tee $P/unexport; done
sudo modprobe -r pwm_pca9685                           # 15-B면 sudo rmmod pca9685_simple
sudo dtoverlay -r i2c-pwm-pca9685a
```

```bash
# [Pi] 칩 초기화. 드라이버가 붙지 않았을 때만(i2cdetect에서 40이 UU가 아님)
i2cset -y 1 0x40 0x00 0x11                             # MODE1 기본값 SLEEP|ALLCALL
i2cset -y 1 0x40 0xfe 0x1e                             # PRE_SCALE 기본값 30(SLEEP 중이라 반영됨)
i2cget -y 1 0x40 0x00; i2cget -y 1 0x40 0xfe           # 0x11, 0x1e
```

```bash
# [Pi] 15-B 적재와 되돌리기
echo 'blacklist pwm_pca9685' | sudo tee /etc/modprobe.d/pca9685-simple.conf
sudo dtoverlay i2c-pwm-pca9685a
sudo insmod ~/bsp/modules/pca9685_simple.ko

# 위 15-A와 같은 sysfs 명령으로 비교한 뒤 원복

i2cget -f -y 1 0x40 0x00                               # 0x30(SLEEP|AI)
sudo dtoverlay -r i2c-pwm-pca9685a
sudo rm /etc/modprobe.d/pca9685-simple.conf
```

## 6. 트러블슈팅과 한계

트러블슈팅: [pwm 6장](../components/pwm.md#6-트러블슈팅)

- **미검증:** 서보 실구동, 핀의 실제 파형(주기·duty 정확도, OE·MODE2 출력 구동). 보드 검증은 레지스터 값과 debugfs까지다.
- **데이터시트 대조 확인 필요:** MODE1 기본값 `0x11`(읽은 값 `0x11`, RESTART 표시 시 `0x91` 가능), PRE_SCALE 기본값 `0x1E`, LEDn 전원 직후 기본값, 3.3V 레일 전류 합계와 모듈 풀업 값.
- **한계:** `pca9685_simple`은 학습용이다. ALL_LED 채널·`invert`·`open-drain`·GPIO·`pm_runtime`이 없다. 18단계 Yocto 이미지에는 업스트림 `pwm-pca9685`를 쓰고, 6.6 커널에 `devm_pwmchip_alloc`이 있는지는 18단계에서 소스로 확인한다.
